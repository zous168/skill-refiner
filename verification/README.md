# Published verification summary

This directory contains a portable summary of the local verification completed
on 2026-10-18 for skill-refiner 0.3.0. It is an export of recorded results, not
another test run or a substitute for the complete raw archives.

- [Results](v0.3/results.json): counts, engine matrix, limitations and provenance.
- [Tested source hashes](v0.3/source-sha256.json): SHA256 values for the exact Skill
  files used in the successful live verification, excluding local runtime settings.

The business example was a local JSON inventory/order allocation Skill, created
from a prose requirement without a starting Skill. Its contract, implementation
and reviewed normal/boundary/error suites were generated by real models. After
controller compatibility fixes, the final CLI run resumed those preserved
artifacts and reran every verdict: Codex and native Codex children each passed
5 development and 6 acceptance cases, with 22 fresh target evaluations. This is
not a claim of an unattended first-attempt success.

A separately declared fault changed inventory subtraction to subtract zero in a
copy of the accepted Skill. Codex reproduced the defect; the first native run
instead failed because it supplied an extra argument. A native repair Agent
distinguished the causes and repaired the supporting script. A second repair-role
review cleared the remaining execution concern without changing code. Both
complete development matrices and the final acceptance matrix passed: 34 actual
target evaluations. This supplemental harness used the production repair,
standards review and Matrix components with the frozen real suites; it was not
another fresh CLI creation/planning run.

The 45 unit/integration checks use deterministic model doubles, with real skill-up
execution where applicable. They are distinct from the live model results above.
The generated business implementation also passed 27 independent direct-code
probes. Cursor authentication, live custom-model endpoints and external-service
business integrations remain unverified. Python execution observations are not
an OS isolation guarantee.

Complete transcripts, diagnostic archives, original failures, frozen contracts,
patches and a hash index remain in the original local `.refiner-runs/` directory,
which is excluded from Git. The detailed repository reports retain their local
evidence paths. No raw result or lock was rewritten for this publication.
